\title{An AI-Aware Security Gateway for Retrieval-Augmented Chatbots:\\
Model-Independent Controls and a Cross-Model Evaluation}

% Anonymized for PRDC 2026 double-blind review. Fill in for camera-ready.
\author{\IEEEauthorblockN{Anonymous Author(s)}}

\maketitle

\begin{abstract}
Retrieval-augmented generation (RAG) lets chatbots answer from an organisation's
own documents, but it widens the attack surface: untrusted retrieved content and
user input reach the model and its tools directly, opening the door to prompt
injection, retrieval-time data leakage, and tool abuse. The usual defence trusts
the underlying model's safety alignment, a property of one component that an
operator can neither inspect nor guarantee and that changes with every model
update. We instead treat injected content as a fault to be contained rather than
detected, and place the security-relevant decisions in a gateway around the model:
an AI-aware Policy Enforcement Point on the RAG pipeline that applies five controls,
two structural (retrieval authorisation, scoped tools) proved sound for every model,
a partially-structural context quarantine sound under one stated assumption, and two
heuristic (input filtering, output redaction) for defence in depth. We map the
controls onto the OWASP Top 10 for LLM Applications, integrate the gateway with a
production tourism-services platform's document store and identity provider as a
feasibility exercise (no user traffic was served), and evaluate it on a controlled
synthetic corpus across a deterministic worst case and six open-source models
(7B--70B). With the gateway on, attack success is zero by our rubric for every model,
including the 70B spot-check, on all six evaluated scenarios (one representative
payload per OWASP class), while the
guardrails-off baseline varies from model to model. A factorial sweep shows the
structural controls, not a hardened prompt, close the attacks alignment misses, and
the gateway neutralises attacks that two single-component guardrails, Llama Guard and
NeMo Guardrails, miss. On \fpN{} benign queries across five models the gateway
over-blocks \fpPoneCount{} inputs and alters \fpPfourTotal{} answers, and entitled
users retain access to restricted documents, so the containment costs little utility.
The safety these controls give is model-independent by construction; we claim it
empirically for open-source models from 7B to 70B with lexical retrieval.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Retrieval-augmented generation (RAG) has become the default way to put a large
language model (LLM) to work over an organisation's own documents
\cite{lewis2020rag}: a user question is answered not from the model's weights
alone but from passages retrieved at query time from a private corpus. That design
is also where the security model breaks down, because two untrusted inputs now
reach the model and any tools it can call, namely the user's message and the
content of the documents the retriever returns. An attacker who controls either
one can try to override the system prompt, read documents they are not entitled
to, or drive a connected tool to act on their behalf. Direct and indirect prompt
injection, sensitive-information disclosure, and excessive agency sit among the
most prominent entries in the OWASP Top 10 for LLM Applications
\cite{owasp2025llmtop10,greshake2023indirect,perez2022ignore}.

The common response is to rely on the model's own safety alignment to refuse
malicious instructions, but that is the wrong layer to depend on. Alignment is a
property of a specific model, it varies between models and versions, and an
operator can neither inspect nor guarantee it; a control that holds for one
open-source model may fail on the next, with nothing in the deployment making the
difference visible. From a dependability standpoint the model is a component whose
failure modes under adversarial input are unknown and unverifiable, and a system that
relies on such a component to enforce its own security policy has no containment
boundary. We take the opposite position and place the security-relevant decisions in
a gateway around the model rather than in the model itself. The gateway sits on the
RAG pipeline as a Policy Enforcement Point and applies five controls regardless of
which model produces the answer. Two are least-privilege guarantees that hold by
their position in the pipeline, a third is partially structural, and the remaining
two are best-effort heuristic checks for defence in depth. Retrieval authorisation
and scoped tools are standard access-control practices, least privilege applied to
retrieval and tool use \cite{saltzer1975protection}; rather than inventing controls,
we compose them into a model-independent gateway and measure, across models, how
much safety comes from the gateway versus from a given model's alignment.

We evaluate six attack scenarios, one per addressed OWASP class: S1 direct prompt
injection, S2 indirect injection through a retrieved document, S3 RAG data leakage,
S4 tool abuse, S5 system-prompt leakage, and S6 improper output handling. The paper
makes three contributions: a model-independent gateway of five controls with a formal
threat model and security properties (Sections~\ref{sec:threat}--\ref{sec:owasp}); a
feasibility integration of the gateway with a chatbot wired to a production
tourism-services platform's document store and identity provider
(Section~\ref{sec:deployment}); and a cross-model evaluation attributing the
secure-mode safety to the structural controls rather than a hardened prompt
(Section~\ref{sec:evaluation}). That evaluation pairs the model-dependent
guardrails-off baseline against the uniform gateway-on behaviour and adds a full
$2^5$ factorial sweep, external guardrail baselines, a second-scorer validity check,
a negligible-overhead analysis, and a utility study: over-blocking on \fpN{} benign
queries across five models and an entitled-user access check. The evaluation code,
rubric, corpus, and every stored transcript are in the anonymous
artifact.\footnote{Code, rubric, corpus, transcripts, and data: \artifacturl.}

\section{Background and Threat Model}
\label{sec:threat}

A RAG chatbot answers a user message $m$ from a corpus $D$ of documents. A
retriever selects a small set $R \subseteq D$ relevant to $m$, the model generates
a response from the system prompt, $m$, and the text of $R$, and the response may
request calls to external tools. Both $m$ and the content of $R$ are
attacker-influenced, so every stage downstream of retrieval is an opportunity for
the attacker.

We model the deployment with users $U$ and documents $D$. Each user $u$ holds
clearances $\mathit{cl}(u)\subseteq C$ and each document $d$ a label
$\mathit{acl}(d)\in C$; $u$ may read $d$ only if $\mathit{acl}(d)\in\mathit{cl}(u)$,
and we write $A(u)=\{d\in D:\mathit{acl}(d)\in\mathit{cl}(u)\}$ for the documents $u$
is entitled to. The system prompt $\mathit{sys}$ and the gateway configuration are
trusted developer artefacts. The user message $m$ and the body of every retrieved
document are untrusted data: they may inform an answer but must never be promoted to
instructions.

The attacker aims to disclose a restricted document, execute an out-of-scope action,
exfiltrate the system prompt, or emit active content, and has two capabilities:
(C1) it submits arbitrary user messages, including ones that try to override the
system prompt or drive the tools (direct injection); and (C2) it plants arbitrary
content in documents the retriever may later surface, so that retrieved text carries
instructions (indirect injection and corpus
poisoning)~\cite{greshake2023indirect,zou2024poisonedrag}. It controls neither the
gateway configuration nor the access labels.

This is the confused-deputy problem~\cite{hardy1988confused}. Without the gateway
the model is a deputy that acts on whatever text reaches it, exercising the union of
the developer's authority (its tools) and any authority implied by untrusted content;
injected text borrows that authority. The gateway re-imposes the principal's
authority at the pipeline boundary, binding retrieval to $\mathit{cl}(u)$ before the
deputy acts and tool execution to a fixed scope after it, so that a misled deputy
still cannot exceed the authority enforced around it.

The guarantees of Section~\ref{sec:properties} rest on three assumptions, stated so
their scope is explicit. (A1) Access labels and the principal-to-clearance binding
$\mathit{cl}(u)$ are authentic and tamper-proof, enforced by the document store and the
identity provider (in deployment, by verifying the caller's token against the realm's
JWKS); if either can be forged, retrieval authorisation no longer holds.
(A2) For the heuristic controls only, the attacker is non-adaptive: one who knows
the filters' patterns can craft obfuscated bypasses, and such evasion is out of
scope for P1 and P4, though not for the structural controls, which never inspect
content. (A3) For the quarantine guarantee, the model honours the untrusted-data
fence; we make this precise in Section~\ref{sec:properties} and show the reference
gateway satisfies it by construction.

The gateway enforces the five controls of Table~\ref{tab:props}: two structural
(P2, P5), a partially-structural quarantine (P3), and two heuristic (P1, P4). The next
two sections present the design and then prove which guarantees hold for every model.

\section{The AI-Aware Security Gateway}
\label{sec:gateway}

The gateway is a single pipeline parameterised by a security policy
(Fig.~\ref{fig:gateway}). In the vulnerable configuration every control is off
and a weak, secret-bearing system prompt is used, so the user message and
retrieved content flow straight to the model and its tools; in the secure
configuration all five controls are on and a hardened prompt is used. Expressing
the difference as one policy object rather than as branches in the code keeps the
before/after comparison exact and makes the gateway a drop-in component for any RAG
application. The controls act in pipeline order: the input filter rejects an
injecting message before retrieval; retrieval authorisation restricts the
candidate set to documents the user may read, so a restricted document is never
placed in the context; context quarantine fences what is retrieved; the model then
generates; output redaction strips secret and active content on the way out; and
scoped tools validate every requested call before executing it.

The design claim is that P2 and P5 do not depend on the model. Retrieval
authorisation filters candidates before the model runs, so even a model that fully
obeys an injected instruction cannot disclose a document it never received, and a
scoped tool refuses an out-of-policy call even if the model emits it verbatim.
Whether a model refuses a naive ``ignore your instructions'' prompt is, by
contrast, an alignment property that varies across models. The evaluation
quantifies both halves of this picture and, through the factorial sweep of
Section~\ref{sec:evaluation}, attributes the secure-mode result to the controls
rather than to the hardened prompt and isolates the marginal effect of each
individual control.

The gateway ships as a library configured by the policy object alone, with four
pluggable interfaces so the same controls apply across deployments without touching
the control logic: a corpus (documents with access labels), a principals source
(identity to clearances), a model provider (the stub, a local Ollama model, or any
OpenAI-compatible endpoint), and an optional offline judge.
Section~\ref{sec:deployment} binds the corpus and principals interfaces to a
production platform while the evaluation swaps only the provider across seven
backends; the control implementations are byte-for-byte identical throughout, which
is model-independence in practice as well as in the proofs.

\section{Security Properties}
\label{sec:properties}

We give the gateway a semantics that makes precise which guarantees hold for every
model and which are conditional. A model is any function $M$ mapping an input triple
$(\mathit{sys},m,X)$ to a response $r$ and a set of tool calls $\mathcal{C}$. We
quantify over $M$, so a statement proved for all $M$ depends on no model's
alignment. On a request $(u,m)$ the secure pipeline retrieves
$R=\mathit{topk}(m,A(u))\subseteq A(u)$, fences it as $X=\mathit{quarantine}(R)$,
computes $(r,\mathcal{C})=M(\mathit{sys},m,X)$, releases $r'=\mathit{redact}(r)$, and
executes $\mathit{Exec}=\{c\in\mathcal{C}:\mathit{name}(c)\in\mathit{allow}\wedge
\mathit{args}(c)\in\mathit{scope}\}$. The quarantine transform wraps each chunk in an
untrusted-data fence, strips HTML comments, and neutralises embedded control
markers.

\subsection{Model-independent guarantees}

\begin{proposition}[P2, retrieval-authorisation soundness]
\label{prop:p2}
For every model $M$, user $u$, and message $m$, the model input contains content
only from documents in $A(u)$; consequently no document $d$ with
$\mathit{acl}(d)\notin\mathit{cl}(u)$ influences the response.
\end{proposition}
\begin{proof}
By A1 the access labels and the user's clearances $\mathit{cl}(u)$ are authentic, so
$A(u)$ is the true authorised set.
Retrieval restricts candidates to $A(u)$ before $M$ is invoked, so $R\subseteq A(u)$
and $M$'s input is a function only of $(\mathit{sys},m,\mathit{quarantine}(R))$. No
$d\notin A(u)$ appears in that input, for any $M$.
\end{proof}

\begin{proposition}[P5, tool-scope soundness]
\label{prop:p5}
For every model $M$ and output $(r,\mathcal{C})$, a call $c$ is executed only if
$\mathit{name}(c)\in\mathit{allow}$ and $\mathit{args}(c)\in\mathit{scope}$.
\end{proposition}
\begin{proof}
$\mathit{Exec}$ filters $\mathcal{C}$ by the scope predicate before execution,
independent of how $\mathcal{C}$ was produced.
\end{proof}

\begin{proposition}[P3, quarantine completeness]
\label{prop:p3c}
For every model $M$, user $u$, and message $m$, every retrieved chunk reaching the
model is enclosed in the untrusted-data fence and carries no marker from the set
that $\mathit{quarantine}$ neutralises.
\end{proposition}
\begin{proof}
The pipeline applies $\mathit{quarantine}$ to every element of $R$ before forming
$X$; by construction $\mathit{quarantine}$ wraps its argument in the fence and
removes the neutralised markers, independent of $M$.
\end{proof}

Propositions~\ref{prop:p2}--\ref{prop:p3c} hold by the position of the control in
the pipeline, before $M$ (P2, P3) or after it (P5), which is the precise sense in
which they are model-independent. P2 and P5 are sound regardless of the model: a
document the user may not read never enters the model input, and a call outside
scope is never executed, whatever $M$ emits. P5 bounds the \emph{shape} of an
executed call, its name and arguments lie in scope; it does not bound the
information a within-scope call may carry, a limit we make explicit in
Section~\ref{ssec:nonguar}. The confused deputy can be misled, but it cannot exceed
the authority the gateway enforces at its boundaries.

\subsection{A conditional guarantee for quarantine}

Quarantine completeness is structural, but whether fencing actually stops an
embedded instruction depends on the model honouring the fence. We isolate that
dependence in a single assumption. The fenced region may legitimately inform the
answer; what must not happen is for it to change the tool calls the model makes.

\begin{definition}[Fence-respecting model]
\label{def:fence}
$M$ is \emph{fence-respecting} if the tool calls it emits are invariant under changes
confined to the fenced region of its context: for any $X,X'$ that agree outside the
fence, $M(\mathit{sys},m,X)$ and $M(\mathit{sys},m,X')$ emit the same tool calls
$\mathcal{C}$. The free-text answer $r$ may differ, as it may legitimately use the
fenced content.
\end{definition}

\begin{proposition}[P3, quarantine soundness under A3]
\label{prop:p3s}
If $M$ is fence-respecting, then no content in a retrieved document changes $M$'s
tool calls: a tool call the request would not otherwise emit cannot be induced
through retrieved content.
\end{proposition}
\begin{proof}
By Proposition~\ref{prop:p3c} every retrieved chunk reaching $M$ lies inside the
fence. Replacing the embedded content with inert text is a change confined to the
fenced region, so by Definition~\ref{def:fence} the tool calls are unchanged.
\end{proof}

The reference gateway realises a fence-respecting model by construction: its
deterministic backend applies a fence-stripping step that removes the fenced region
before scanning for commands, so its tool calls cannot depend on fenced content and
Assumption A3 holds exactly. The stub is therefore both the alignment worst case (it
never refuses) and a fence-respecting model, so its secure-mode results show what
the structural controls achieve when alignment contributes nothing; they are not an
upper bound on compromise for a model that violates A3, which is why P5 caps tool
execution and P3 is only partially structural. Whether a production model satisfies
A3 is an empirical question; we pair P3 with output redaction (P4), which is what
closes S5-style disclosure rather than this conditional guarantee.

\subsection{Non-guarantees: the heuristic controls}
\label{ssec:nonguar}

The input filter P1 rejects a message matching a finite injection-pattern set $\Pi$,
and output redaction P4 substitutes a finite set $\Sigma$ of secret and
active-content shapes in the response. Neither is sound. For any finite $\Pi$ there
are semantically equivalent messages outside it (paraphrase, homoglyph substitution,
instruction splitting), and for any finite $\Sigma$ there are secret or
active-content encodings it does not match; an attacker who knows the patterns can
evade them, which is Assumption A2 made explicit. P1 and P4 are therefore defence in
depth, not guarantees. The structural controls bound the damage regardless: by
Propositions~\ref{prop:p2} and~\ref{prop:p5} an attacker who evades P1 and P4 still
cannot cause the model to receive an unauthorised document or to execute an
out-of-scope tool call. Scoped tools share this character: P5 refuses any
out-of-scope call, but a within-scope call (internal recipient, body within the cap)
can still carry bounded data, so P5 limits rather than eliminates tool-mediated
disclosure; the S4 result measures the external-recipient attack P5 provably
refuses. This division of labour is the design principle of the gateway: the
heuristics reduce incidence, the structural controls cap impact.

\section{Integration with a Production Platform}
\label{sec:deployment}

The target application is the help assistant of a regional tourism-services
platform, a microservice system whose knowledge-base service exposes documentation
articles over a REST API and whose identity is managed by a Keycloak realm
(Fig.~\ref{fig:arch}). Authenticated platform users (visitors, analysts, and
administrators, expressed as realm roles) ask natural-language questions about the
platform's indicators, data sources, and documentation; the assistant answers from
the knowledge-base articles and may call one action tool, sending a message on the
user's behalf, whose recipient set and body size the scoped-tool control bounds. A
new chatbot microservice imports the gateway as a library and sits behind the
platform's nginx reverse proxy on a dedicated route; each request carries the
user's bearer token and returns the answer together with the gateway's audit trail
(retrieved document identifiers, control decisions, tool results), and an operator
switch selects the secure or vulnerable policy for demonstrations. The service binds
the gateway's two deployment interfaces to the platform: the corpus interface loads
documents from the knowledge-base REST API, and the principals interface validates
the caller's Keycloak bearer token against the realm's JWKS and maps the realm roles
it carries to gateway clearances (every caller implicitly holds \texttt{public}), so
retrieval authorisation (P2) runs on real identities. A document's access label is
carried by an \texttt{acl} field added to the knowledge-base record schema. Only
these two adapters are platform-specific; the five control implementations are the
same code exercised in the evaluation. This demonstrates that the gateway slots into
a real document store and identity provider without changes to the control logic.
It is an integration and feasibility result: no integrated request was served
against user traffic, and we report no operational metrics, latency, or real-user
study from the deployment.

\section{Evaluation}
\label{sec:evaluation}

\subsection{Setup}
The question is whether composing the controls yields model-independent safety,
and how the guardrails-off baseline varies across models. We run the six scenarios
in two modes, vulnerable (every control off, the baseline) and secure (the gateway
on), over a deterministic stub model and six open-source instruct models:
Llama~3.1~8B, Qwen2.5~7B, Mistral~7B, Gemma~3~12B, and Phi-4~14B served locally
through Ollama, and Llama~3.1~70B on a rented A40 GPU. The main grid covers all six
models in both modes. The factorial sweep, dose-response, temperature-0.7,
scoring-validity, and utility analyses that follow cover the five locally-served
models (7B--14B) and the stub; the remotely-served 70B enters only the main
single-run grid as a scale spot-check, without the per-cell transcripts, judge
re-scoring, or annotation the other models carry, so its rows are indicative rather
than audited. Decoding is greedy (temperature~0, fixed seed) so each cell is
deterministic and reported directly; a temperature-0.7 run later checks that the
findings survive sampling. The stub is a naive instruction-follower with no refusal
mechanism that echoes whatever an injection asks for, fixing the worst case and
making the controls' effect reproducible. We report, per (model, scenario, mode),
the attack success rate (ASR) and the refusal rate (the model declined, an alignment
signal). Structural controls do not all register as an explicit block: P1 and P5
hard-reject observably, whereas P2 and P3 prevent the outcome by suppression (the
unauthorised document or instruction never reaches the model), which shows up as
reduced ASR rather than a separate signal. Outcomes are scored by a transparent
deterministic rubric keyed to each scenario's markers and specified in the released
code.

\subsection{Model-independent safety and the alignment baseline}
With the gateway on, ASR is zero by the rubric for every model on every scenario.
This uniform closure is an empirical observation about the full gateway, not a single
guarantee: only data leakage (S3) and tool abuse (S4) follow from the
model-independent structural controls (P2, P5); direct injection (S1) is caught by the
input filter or redaction, system-prompt leakage (S5) by the hardened prompt and
redaction, and the indirect attacks (S2, S6) by quarantine, which on the evaluated
payloads strips the embedded markers structurally
(Proposition~\ref{prop:p3c}); the conditional fence-respecting guarantee
(Proposition~\ref{prop:p3s}) governs only a residual plain-text directive that
survives stripping. The structural part holds for every model by construction; the
cross-model data is what makes the rest credible. With guardrails off the picture
inverts (Fig.~\ref{fig:heatmap}): the unaligned stub is compromised on all six
scenarios, while the six aligned models are compromised inconsistently, with mean
vulnerable ASR ranging from $0.17$ (Llama~3.1~8B, Phi-4~14B) to $0.50$
(Mistral~7B). The variation is attack-specific rather than a clean model ranking,
since only data leakage (S3) and tool abuse (S4) differ across models while S1,
S2, and S6 are handled by every aligned model. Scale does not buy safety:
Llama~3.1~70B (mean $0.33$) leaks the restricted document on S3 where its 8B sibling
refuses. System-prompt leakage (S5) succeeds in vulnerable mode on every instrumented
model and on the 70B spot-check, including the largest and best aligned, because the
oblique request slips past the alignment that refuses the blatant variant (S1). The
gap between the two modes is the safety the gateway adds on top of whatever alignment
a model happens to provide, and it is the same gap for every model.

\subsection{Scoring validity}
Two scorer checks confirm the secure result is not an artefact of the rubric (the
prompt and the decoder are checked by the factorial and temperature sweeps below).
Two of the authors independently annotated the 72 instrumented cells (stub and the
five local models, six scenarios, two modes) from the stored outputs with a binary
attack/no-attack label, blind to the rubric's label; they agree on 67 (93\%;
Cohen's $\kappa$ = \humankappa, almost perfect), and the per-cell two-annotator labels
are in the released artifact. The five disagreements are all in secure mode (four on
S5, one on S3), where one annotator counted the model echoing its secret-free
hardened prompt, after the override code was redacted, as a partial disclosure while
the other and the rubric did not. This is a definitional choice about residual
disclosure rather than an attack the gateway let through; a stricter no-disclosure
rubric would also redact the prompt scaffold. As the second check we re-scored every
stored output with an LLM judge (Llama~3.1~8B reading each transcript and the
scenario goal); judge and rubric agree on 63 of the 72 cells (88\%,
Table~\ref{tab:scorer}), and the judge confirms the zero attack successes the rubric
assigns in secure mode. The judge is a same-family cross-check rather than an
independent one, as Llama~3.1~8B is itself an evaluated model and backs the NeMo
baseline; the blind human double-annotation is the primary independence evidence,
with the caveat that the two annotators are authors.

\subsection{Attribution: which lever closes which attack}
The factorial sweep separates the prompt from the controls
(Table~\ref{tab:factorial}). Hardening the prompt alone leaves the structural
attacks untouched: data leakage and tool abuse stay open until retrieval
authorisation and scoped tools are added, which close them regardless of the
prompt, whereas system-prompt leakage is closed by the hardened prompt (which simply
carries no secret) and not by P2 or P5 (the one-sixth dip under the structural pair
alone is a single backend that happened not to echo the prompt in that greedy run,
not a closure); the residual $0.17$ in the hardened-prompt column is the
worst-case stub, which the prompt cannot help and which only output redaction closes.
The hardened prompt does not merely fail on data leakage but slightly worsens it (S3
rises from $0.67$ to $0.83$), which is exactly why data leakage needs a structural
control rather than prompt engineering. The two levers are therefore orthogonal, and
the structural controls are the ones that act where alignment fails. A full $2^5$
sweep over every control combination isolates each control
(the appendix, Table~\ref{tab:isolation}): on the worst-case stub, enabling one control at a time
closes each attack with the control mapped to it, and shows that system-prompt
leakage is closed only by output redaction, not by the input filter, since the
oblique request bypasses it. A pre-redaction re-scoring supports the same reading: in
secure mode the model's output before the filter is already clean for every real
model on S5 and S6, so quarantine and the hardened prompt prevent the leak upstream
and the output filter is only a backstop, relied on solely by the naive stub.

\subsection{Comparison with off-the-shelf guardrails}
Two off-the-shelf guardrail systems cover far less of this surface
(Fig.~\ref{fig:baseline}). Llama Guard~3 \cite{inan2023llamaguard}, a
content-safety classifier, flags none of the six attack inputs, which read as
benign, and only three of the six worst-case outputs, missing data leakage, tool
abuse, and prompt leakage; NeMo Guardrails' \cite{rebedea2023nemo} self-check input
rail, backed by Llama~3.1~8B, blocks only the blatant direct injection, one of six.
Both are single-component classifiers rather than full pipelines, so the comparison
shows that isolated classifiers miss structural attacks, not a like-for-like ranking.
Re-running the guardrails-off baseline at temperature~0.7 with ten seeded samples per
cell leaves the picture unchanged: the cross-model variation persists (mean per-model
vulnerable ASR $0.07$--$0.60$) and sampling surfaces, if anything, more successes.
This sampled sweep covers the vulnerable baseline only.

\subsection{Operational cost}
The controls are pure functions of the request, so the gateway adds negligible latency.
Timing each control in isolation over $2\times10^{5}$ calls gives medians of
$0.3$--$0.9\,\mu$s for the input filter, retrieval authorisation, quarantine, and
tool validation, and $5.3\,\mu$s for output redaction (the most regex-heavy),
Fig.~\ref{fig:overhead}; the five together cost about $7.5\,\mu$s per query, over five
orders of magnitude below the per-model median inference time of
$1.5$--$7.6$\,s we measured (Llama~3.1~8B to Phi-4~14B).

\subsection{Utility: over-blocking and entitled access}
\label{ssec:utility}
A security layer that blocks legitimate use is not deployable, so we measure the
utility cost from two sides. The first is over-blocking by the two
content-inspection controls, which can in principle fire on benign traffic. We built
a corpus of \fpN{} benign questions a user of such a chatbot might ask, spanning
travel and local services, IT help-desk questions answerable from the public
articles, routine HR and account questions that request no restricted data, and
general customer service; \fpNearMiss{} of them are deliberate near-misses that use,
in innocent senses, the vocabulary the injection patterns key on (``booking
system'', ``follow the instructions on the sign'', ``ignore the rain forecast'',
``reset my password'', ``the secret to a good espresso''). Every question was run
through the secure pipeline on each of the five locally-served models
(Table~\ref{tab:fp}). The input filter is deterministic and model-independent: it
rejected \fpPoneCount{} of \fpN{} questions\fpPoneNote. Output redaction altered
\fpPfourTotal{} of the \fpPfourRuns{} answers across the five models\fpPfourNote.
The near-miss subset behaves no differently from the rest. The corpus is single-site
and author-written, so we read this as evidence that the patterns are not
trigger-happy on realistic traffic rather than as a precision guarantee; a
deployment would measure the same two rates on its own logs.

The second side is whether retrieval authorisation over-blocks users who are
entitled to a restricted document, since P2 filters the candidate set for everyone.
We posed \fpUtilN{} legitimate questions whose correct answer requires a restricted
record (the executive-compensation bands and the production-credentials note) as an
entitled principal (the HR user for the compensation record, the security operator
for the credentials record) and as the \texttt{public}-only support agent, on the
stub and the five models. For the entitled principal the restricted document was
retrieved and placed in the context in \fpUtilRetrieved{} of \fpUtilRuns{} runs; for
the support agent it was retrieved in none, as Proposition~\ref{prop:p2} requires.
The gateway therefore never withheld an entitled document. What the entitled user
actually received then depended on the two remaining layers. Output redaction masked
the literal credential strings in \fpUtilRedacted{} answers, since P4 strips secret
shapes regardless of who asks; that is P4 acting as designed (a chatbot should not
paste production keys into a chat window), and an operator who wants the raw value
would scope the redaction set per clearance. And in \fpUtilRefused{} runs the model
itself declined to state the retrieved figures to a user entitled to them
(\fpUtilRefusedByModel{}), an over-refusal by the model's alignment that the gateway
neither causes nor can remove. The two utility costs thus separate cleanly:
containment by the gateway costs the entitled user nothing on retrieval and only the
literal secret string on output, while the model-dependent cost, over-refusal, is one
more reason not to make alignment the enforcement layer.

\section{Related Work}
\label{sec:related}

Prompt injection was characterised by Perez and Ribeiro \cite{perez2022ignore} for
the direct case and by Greshake et al.\ \cite{greshake2023indirect} for the indirect
case, where instructions hidden in retrieved content hijack an LLM-integrated
application; HouYi \cite{liu2024houyi} turned this into a black-box attack framework
against deployed applications, and Liu et al.\ \cite{liu2024promptinjection} give the
first systematic cross-model benchmark. The surface has since been charted by
crowd-sourced attack corpora \cite{toyer2024tensortrust}, indirect-injection
benchmarks \cite{yi2025bipia}, and automatic, transferable payloads produced by
optimisation \cite{liu2024universalinjection}. These works define the classes the
gateway must intercept; rather than a new attack, we contribute a structural layer
measured against them with a guardrails-off baseline.

One line of defence hardens the model itself. StruQ \cite{chen2024struq} and SecAlign
\cite{chen2024secalign} separate instructions from data through structured queries
and preference optimisation, spotlighting marks provenance \cite{hines2024spotlighting},
Jatmo \cite{piet2024jatmo} fine-tunes a model to its task so injected instructions are
not followed, and the instruction hierarchy \cite{wallace2024instructionhierarchy}
trains a model to prioritise privileged messages. These defences are per-model and
re-trainable, and recent work shows alignment can be shallow \cite{qi2024shallowsafety}
or countered only at the representation level \cite{zou2024circuitbreakers}. The
gateway's controls sit outside the model, so the same code applies unchanged across
backends, which we verify cross-model.

A second line constrains the system around the model. Design-pattern catalogues
\cite{beurerkellner2025designpatterns} and the dual-LLM pattern
\cite{willison2023dualllm} isolate untrusted content from privileged action, while
CaMeL \cite{debenedetti2025camel}, information-flow control \cite{wu2024fsecure},
type-directed privilege separation \cite{jacob2025typedirected}, and execution
isolation \cite{wu2025isolategpt} enforce least privilege by construction. The
gateway shares this secure-by-design stance but targets the RAG
retrieval-and-generation path with lightweight controls and reports a guardrails-off
baseline that quantifies what the structural layer adds.

RAG makes the corpus a first-class attack surface. The datastore can be extracted
verbatim through injected instructions \cite{qi2025spillbeans} or probed for
membership \cite{anderson2025ismydata}, its privacy tension has been characterised
\cite{zeng2024goodbad}, and it can be poisoned \cite{zou2024poisonedrag} or backdoored
\cite{chaudhari2024phantom}; SafeRAG \cite{liang2025saferag} benchmarks pipelines
against several such attacks and is the natural integrated comparison target. Model
self-critique such as Self-RAG \cite{asai2024selfrag} complements, rather than
replaces, the structural mediation we add at the retrieval boundary.

Tool-using agents widen the surface again. InjecAgent \cite{zhan2024injecagent} and
AgentDojo \cite{debenedetti2024agentdojo} benchmark indirect injection and defences
for agents, AgentHarm \cite{andriushchenko2025agentharm} measures harmful tool use,
and adaptive attacks break single-layer agent defences \cite{zhan2025adaptiveipi},
which is the empirical case for defence in depth and for structural controls that do
not inspect content. Guardrail classifiers such as NeMo Guardrails
\cite{rebedea2023nemo}, Llama Guard \cite{inan2023llamaguard}, and Granite Guardian
\cite{padhi2024graniteguardian}, and adaptive security services \cite{pfister2025gandalf},
operate alongside such a layer rather than replacing it, as our baseline comparison
shows. We align the threat model with the OWASP LLM Top-10 \cite{owasp2025llmtop10},
the NIST AI RMF \cite{nist2023airmf}, and MITRE ATLAS \cite{mitre2024atlas}.
Table~\ref{tab:positioning} positions representative approaches: ours is the only row
that is model-independent, evaluated cross-model against a guardrails-off baseline,
and RAG-aware at once.

\section{Discussion, Limitations, and Agenda}
\label{sec:discussion}

The structural controls are the load-bearing ones, holding against the stated
threat model regardless of the model, and the factorial confirms the secure result
comes from them rather than from the hardened prompt. Several limitations bound the
claims, and we separate those that concern the mechanism from those that concern
the empirical coverage.

The design carries three trade-offs. The retriever is a lexical (TF-IDF) baseline,
though retrieval authorisation acts on the candidate set independently of how it is
ranked, so the guarantee of Proposition~\ref{prop:p2} is unaffected by the choice of
retriever. The tool protocol is textual, so an aligned model that declines the
literal call syntax lowers vulnerable-mode tool-abuse success; this is an alignment
effect on the baseline, and secure-mode validation overrides it regardless. Output
redaction strips the secret but the model may still echo its secret-free hardened
prompt, the borderline residual-disclosure case noted in the scoring-validity check.

The empirical coverage is deliberately narrow. All models are open-source, from 7B
to 70B, with no commercial models, and the evaluation runs on a controlled synthetic
corpus in a single domain. Because P2 and P5 act by position rather than by
inspecting content, the structural argument does not depend on model scale or domain,
so this caveat concerns how widely we have measured rather than the mechanism itself.
The attack battery is also narrow: one hand-crafted payload per OWASP class scored by
literal markers, so the cross-model ``zero'' is a class-representative demonstration,
not a per-class success rate; the payload-independent structural propositions carry
the class-level claim. The utility study is one author-written corpus and one
entitled-user probe, so it bounds over-blocking on realistic traffic rather than
estimating a precision. Secure-mode cells are a single greedy run,
sampling-invariant for the structural closures (the offending content is removed
before generation) while the temperature-0.7 sweep covers the vulnerable baseline
only. The platform integration is a feasibility result, not an operational study.

What remains open is the adaptive attacker, and we close with the agenda the
artifact is built to support, since the policy object and the pluggable corpus make
each item a configuration rather than a rewrite. (1) \emph{Breadth of payloads.}
The six scenarios are a schema; the BIPIA~\cite{yi2025bipia} indirect-injection
corpus and the AgentDojo~\cite{debenedetti2024agentdojo} tasks map onto S2/S6 and
S4 respectively by loading them through the corpus interface, which turns the
class-representative zero into a per-class rate with confidence intervals and
tests whether the structural closures stay at zero (they must, by
Propositions~\ref{prop:p2} and~\ref{prop:p5}) while the heuristic ones degrade.
(2) \emph{Adaptive red-teaming of the heuristics.} P1 and P4 should be attacked
with paraphrase, encoding, and instruction-splitting variants generated against
the released pattern sets; the quantity to report is not their evasion rate, which
Section~\ref{ssec:nonguar} predicts is high, but the \emph{impact} that evasion
buys once the structural controls cap it, per scenario. (3) \emph{A3 as a testable
property.} Definition~\ref{def:fence} is a metamorphic test: vary only the fenced
region and check that tool calls are invariant. Running it per model yields a
fence-respect score that would let operators pick models for P3, and it is the
first alignment property in this setting that can be measured rather than
trusted. (4) \emph{Semantic retrieval.} An embedding retriever changes what
enters the candidate set but not P2's filter on it; the open question is
embedding-space evasion of ranking and the correctness of label population on a
real corpus, which is where the platform integration should be taken next.
(5) \emph{Operational measurement.} The two over-blocking rates and the entitled
access check of Section~\ref{ssec:utility} are the metrics a deployment should
log continuously; a controlled pilot on the integrated platform, with consenting
users, would give them a base rate and add the latency profile a synthetic run
cannot. An integrated RAG-security baseline such as SafeRAG~\cite{liang2025saferag}
is the natural head-to-head comparison for that study.

\section{Conclusion}
\label{sec:conclusion}

We presented an AI-aware security gateway that defends a RAG chatbot through five
controls applied around the model, its structural controls proved model-independent
and confirmed across open-source models, integrated as a feasibility deployment on a
production platform, and shown to cost little utility. For an operator the message is
to put the security-relevant decisions in an auditable layer around the model rather
than in the model itself: containment by position is the guarantee, and the model's
alignment is a bonus one can measure but should not depend on.

single-control rows on the worst-case stub, where every attack succeeds with all
controls off: it gives the attack success rate with exactly one control enabled.
Each attack is closed by the control mapped to it, data leakage (S3) by retrieval
authorisation (P2), tool abuse (S4) by scoped tools (P5) or quarantine (P3),
indirect injection (S2) by quarantine (P3), improper output (S6) by quarantine (P3)
or output redaction (P4), and direct injection (S1) by the input filter (P1) or
output redaction (P4). System-prompt leakage (S5) is closed only by output redaction
(P4): the oblique request bypasses the input filter, so input filtering alone would
miss it.
